# Codebase Analysis

Analyze the repository in the current working directory and produce a
thorough, opinionated report covering:

1. **Purpose and architecture** — what this project does, how it is
   structured, and the key design decisions you can infer.
2. **State of the code** — overall quality, consistency, test coverage,
   documentation, and dependency health.
3. **Important issues** — bugs, risks, tech debt, security or
   maintainability problems, ordered by importance. Cite concrete files
   and locations.
4. **Possibly overlooked concerns** — issues another analyst might miss.
5. **Recommendations** — the highest-leverage improvements, in priority
   order.

Be specific: reference real files, functions, and code you actually read.
Prefer depth on the most important findings over shallow completeness.
